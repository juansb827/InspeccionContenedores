# Working on InspeccionContenedores

This Java/XML Android app records container-yard/transport inspections, local media and Bluetooth receipts in one `app` module. Start with [documentation index](docs/README.md), [feature behavior IDs](docs/testing/acceptance.md), [current architecture](docs/architecture/current-system.md) and [storage/side-effect inventory](docs/architecture/storage-and-side-effects.md). Evidence labels distinguish source, tests, execution, history and future decisions.

Use a configured compatible JDK/Android SDK and the Gradle wrapper. [Testing baseline](docs/testing/baseline.md) gives verified commands, cache caveats, focused test selection and device-runner instructions. Use `./scripts/check.sh --fresh` for forced JVM/build/lint execution, or repeated `--tests` patterns for focused tests. [Step-03 evidence](docs/testing/step-03-cutover-and-moves.md) records current cutover/move checks and remaining acceptance; step-02 evidence describes its historical unwired preflight. Default Gradle checks are `:app:assembleDebug :app:testDebugUnitTest :app:lintDebug`; building `:app:assembleDebugAndroidTest` does not execute device tests. Release assembly is unsigned and does not authorize distribution.

Keep Java/XML, one module, application identity and direct SQL Server access ([scope decision](docs/decisions/001-modernization-scope.md)). Implementations use lowercase `ui`, `data`, `platform`, small `domain` and `app` packages. [Move inventory/exceptions](docs/architecture/package-moves.md) identifies retained serialized types and stable Android entry bridges. Preserve form metadata/hidden-field binding, entry/exit/read-only distinctions and Android entry points. Avoid combining package moves, behavior fixes, dependencies and storage changes in one change.

[Storage policy](docs/modernization/storage-version-policy.md) governs the **implemented schema-1 JSON cutover**, not permission to reset arbitrary files. Read [current schema/recovery](docs/architecture/draft-schema-v1.md) before touching storage. Preserve public photos/videos, independent media index and publication/recovery journals; distinguish unsupported formats from corruption/unknown/I/O faults. Retained models/cache values/widget bundles/publication and recovery types still have active serialization identities. Replace their contracts or provide tested state handling before moving/changing them; matching UIDs alone cannot repair class renames. Do not enable dormant upload services or replay uncertain SQL writes/printing.

Use sanitized fixtures and fakes by default; SQL dialect/transaction checks need a dedicated test SQL Server. Never use production services/settings or commit credentials/customer data. Choose existing focused tests for affected behavior, then appropriate build/lint checks; update stable behavior IDs/acceptance evidence with intentional behavior changes. Suspected defects require separate decisions, not silent normalization of baseline docs.

Preserve unrelated working-tree edits. Read current files before editing; consult the [master plan](docs/modernization/00-master-plan.md) and authorized step. Do not begin later phases merely because their instructions exist. Record unperformed checks honestly and retain historical evidence/links.
