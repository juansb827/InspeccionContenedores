# Working on InspeccionContenedores

This Java/XML Android app records container-yard/transport inspections, local media and Bluetooth receipts in one `app` module. Start with [documentation index](docs/README.md), [feature behavior IDs](docs/testing/acceptance.md), [current architecture](docs/architecture/current-system.md) and [storage/side-effect inventory](docs/architecture/storage-and-side-effects.md). Evidence labels distinguish source, tests, execution, history and future decisions.

Use a configured compatible JDK/Android SDK and the Gradle wrapper. [Testing baseline](docs/testing/baseline.md) gives verified commands, cache caveats, focused test selection and device-runner instructions. Use `./scripts/check.sh --fresh` for forced JVM/build/lint execution, or repeated `--tests` patterns for focused tests. [Step-02 evidence/gates](docs/testing/step-02-regression.md) records seam limits and the unwired format probe. Default Gradle checks are `:app:assembleDebug :app:testDebugUnitTest :app:lintDebug`; building `:app:assembleDebugAndroidTest` does not execute device tests. Release assembly is unsigned and does not authorize distribution.

Keep Java/XML, one module, application identity and direct SQL Server access ([scope decision](docs/decisions/001-modernization-scope.md)). Current packages are `Interfaz`, `Mundo`, `CustomView`, `Other`; proposed package separation is not implemented. Preserve form metadata/hidden-field binding, entry/exit/read-only distinctions and Android entry points. Avoid combining package moves, behavior fixes, dependencies and storage changes in one change.

[Storage policy](docs/modernization/storage-version-policy.md) accepts retirement of old drafts/unused uploads **in a future cutover**; it is not current behavior or permission to reset arbitrary files. Preserve public photos/videos, independent media index and publication/recovery journals; distinguish unsupported formats from corruption/unknown/I/O faults. Audit all serialized consumers before moving models. Do not enable dormant upload services or replay uncertain SQL writes/printing.

Use sanitized fixtures and fakes by default; SQL dialect/transaction checks need a dedicated test SQL Server. Never use production services/settings or commit credentials/customer data. Choose existing focused tests for affected behavior, then appropriate build/lint checks; update stable behavior IDs/acceptance evidence with intentional behavior changes. Suspected defects require separate decisions, not silent normalization of baseline docs.

Preserve unrelated working-tree edits. Read current files before editing; consult the [master plan](docs/modernization/00-master-plan.md) and authorized step. Do not begin later phases merely because their instructions exist. Record unperformed checks honestly and retain historical evidence/links.
